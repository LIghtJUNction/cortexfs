# CortexFS：Hacker News 选题可行性扫描

日期：2026-11-08（UTC；当日 Asia/Taipei）  
状态：研究记录与候选验证；尚未确定新的独立产品。  
范围：以当日 HN 首页、Show HN 和近一个月讨论为发现入口，核对原帖、官方文档与项目 README。没有运行下列竞品，没有采访用户，不能把文档功能视作质量或采用率证明。

## 阅读提纲

1. 最新讨论暴露了哪些具体问题。
2. 哪些直觉上的选题已经有直接替代。
3. 为什么优先考虑现有开发工具生态里的小扩展。
4. 候选验证如何控制安装、维护和开发成本。

## 1. 当前判断

**建议离开“通用 Agent 基础设施”的宽定位，优先研究 GitHub 代码审查中的一个重复操作。** 候选问题是：作者更新 PR 后，审查者如何逐条核对上次意见附近的代码变化。选择它的理由是工作流程具体、目标用户可识别、可以沿用已有 Git 和 GitHub CLI，且效果可以用实际审查任务验证。这是项目判断，不是已经证实的市场结论。

**本轮还不足以支持独立重写 CortexFS。** 几个看似合适的轻量工具，在查阅现有项目后发现已经有高度重合的实现。下一步应先使用现有工具，再判断是否存在一个重复、明确、值得维护的缺口。旧定位讨论稿只是历史提案，不是本轮采用的设计。

## 3. 查到直接替代后，调整了哪些选题

**已有产品不是自动否决理由，但它们改变了新项目的举证责任。** 不能只换语言、名称或包装方式，就把现成功能当作新价值。这里的“暂不独立立项”指先验证差异，不是否认问题本身。

| 原候选 | 一手资料确认的替代 | 本轮决定 |
| --- | --- | --- |
| Agent 配置安全检查 | Clauditor 已提供配置范围扫描、可扩展规则及 CI 使用方式。[S8] | 先评估现有规则是否漏掉真实案例，优先补规则 |
| 同一回归测试在修复前失败、修复后通过 | PatchProof 已提供 CLI、GitHub Action、常见测试框架适配及环境失败分类。[S9] | 暂不另起同定位工具 |
| 只管理自己启动的进程，到期停止 | ProcLease 已提供所有者标记、期限、日志、续期及预编译包。[S10] | 暂不做新的进程租约管理器 |
| 两个结构化数据文件按 key 比较并生成离线报告 | Dataloupe 已覆盖跨格式比较、单元格变化和独立 HTML。[S11] | 先拿真实文件试用，通用功能组合不足以形成差异 |
| 从最后一次审查开始看 PR 变化及旧评论 | gh-interdiff 已提供增量比较、旧评论位置映射和 gh 扩展安装方式。[S12][S13] | 独立重写理由不足；可验证更窄的复审交互 |

**这些判断来自文档核对，没有声称上述工具已经成熟可靠。** 即使某项目关注度很低，也只能说明公开关注有限；它既不证明市场成立，也不证明软件不好用。真正需要补上的证据是同一批实际任务的对比使用。

## 4. 当前优先候选：以审查意见为入口的 PR 复审

**候选只回答一个问题：上次提出的每条意见，对应的代码后来怎么变了？** 使用者是需要再次检查 PR 的维护者或协作者。输入是已有 PR 与上次审查记录，输出是意见、原始片段、当前变化和线程状态的并列视图。

**现有方案应先试用。** gh-interdiff 已经计算上次审查后的差异并映射旧评论。它要求本地仓库、Git 2.38+ 和已登录的 gh；因此安装容易是针对已有这套环境的人，而不是所有 GitHub 用户。[S12][S13]

**尚待验证的差异是展示入口。** 现有文档主要以文件 diff 为中心。可以验证：维护者是否更需要“我的未解决意见”列表，每条意见直接显示附近代码变化。文档未明确写出这一交互，不等于现有工具绝对做不到。

**若有价值，应优先成为现有工具的补丁或薄扩展。** 代码比较、GitHub 认证、评论拉取和历史版本处理尽量沿用已有实现。只有出现多名用户重复受阻、简单上游补丁不合适的情况，才讨论独立产品。不能由评论状态或附近代码变化自动宣称问题已经修复。

## 5. 安装与复杂度约束

本节是候选的设计约束，不是已达到的性能或兼容性承诺。

- 第一批只面向已有 Git、已登录 gh 和本地仓库的开发者；沿用他们的认证与习惯。
- 首次试用应能对一个已有 PR 直接产生结果；不要求账号注册、数据库或部署服务。
- 只读结果先验证价值。用户能明确知道读取了哪些仓库数据，以及本地留下了什么。
- 若必须先兼容多家代码托管平台、实现完整 Git 客户端或自建 diff 引擎，说明范围已经失控。
- 安装步骤需可检查、可卸载。一行命令只是入口，依赖与认证成本仍须计入。
- 版本缺失、历史被清理或评论无法精确映射时，应明确显示无法对应，避免猜测。
