# CortexFS

CortexFS is a provider-neutral Linux FUSE filesystem for AI API infrastructure.
It exposes API formats, provider instances, models, requests, responses,
threads, tools, MCP, skills, agents, memory, cluster state, audit, and controls
as ordinary filesystem objects.

The mount tree is the ABI:

```text
/
  status
  cap/
  format/
  provider/
  model/
  home/
  group/
  shared/
  ext/
  space/
  agent/
  cluster/
  mcp/
  skill/
  tool/
  memory/
  vector/
  db/
  audit/
  control/
```

CortexFS has one core submission semantic: write a temporary file, atomically
rename it in the same directory to `*.req.json`, read the result from outbox,
and append facts to audit. `channel`, `job`, `hook`, and `workflow` are not core
filesystem directories; external orchestrators should use the generic
inbox/outbox contract.

## Quick Start

```bash
paru -S cortexfs-git
cortex status
```

Mount locally:

```bash
cortex start
export CTX_HOME="/ctx/home/$(id -u)"
```

Submit a file ABI request:

```bash
api="$CTX_HOME/api/openai.chat"

printf '%s\n' '{"messages":[{"role":"user","content":"Reply with cortexfs-ok"}]}' \
  > "$api/inbox/001.tmp"

mv "$api/inbox/001.tmp" "$api/inbox/001.req.json"
printf '1\n' > /ctx/control/drain

cat "$api/outbox/001.resp.json"
```

## Core Idea

CortexFS separates:

- `format/`: protocol shape, such as `openai.chat` or `anthropic.messages`.
- `provider/`: backend or account instances, including official APIs, relays,
  and local runtimes.
- `model/`: model metadata under provider scope.
- `home/<uid>/route/`: user-visible routing decisions.
- `audit/`: observability for requests, routes, policy, execution, and export.

Secrets do not enter the mounted tree. The filesystem only exposes secret
status and active key IDs; real secret values should be resolved by `cortexd`.
