# 性能合同与测量计划

状态：本次没有运行产品或性能测试。以下负载是为重建验收选择的实验方案，
不是原版实测基线或已承诺指标。历史 benchmark JSON 不进入本包；旧开发报告不能
当作新实现的成绩。延迟、吞吐、RSS、CPU、网络和发布大小预算均待测定。

| 关键路径 | 代表性工作负载 | 记录指标与正确性门槛 |
| --- | --- | --- |
| FUSE 元数据与文件 IO | 合成 1/100/10000 个对象；并发 lookup/stat/readdir/read 与原子发布 | 冷/热耗时、吞吐、median/p95、CPU/RSS；无半成品、错误 inode、越权读。 |
| 并行 Agent 与存储 | 1/2/8 个独立 session；同 session 锁竞争；长历史读取 | 排队与服务耗时、吞吐、资源峰值；禁止串 session 或重复副作用。 |
| 慢消费者与中断恢复 | 大输出、慢 CLI/socket、取消、断线与重启 | 缓冲峰值、恢复时长、未完成调用；无无界缓存、静默丢失或伪造 done。 |
| Git 工作区 | 含嵌套子模块/worktree、只读与获准可写挂载的合成项目 | status/diff 与获准编辑成本、扫描/请求数量；权限与数据完整性优先。 |
| CLI 与安装 | 首次/再次启动、本地健康检查、生成切换和失败回滚 | 启动/检查耗时、包/依赖大小；不以跳过预检或关闭权限提高成绩。 |
| 文档与终端呈现 | 长 JSONL/中文流、窄屏、文档初次加载、动效关闭 | 首次可用时间、输出积压、页面/媒体请求、资源大小；键盘与 UTF-8 正确。 |

重建者先给出实际可复制的 benchmark 命令、fixture 种子与规模，再运行。
记录 CPU/架构、RAM、磁盘/文件系统、内核、FUSE、bwrap、实现版本、并发、缓存状态、
预热、样本数、统计口径与原始结果；只在相同条件下比较。远程 provider 耗时要与
本地运行时/排队开销分开，合成端点也须注明。

根据真实结果与目标设备提出预算并明确其依据；预算未确认时写“待确认”，不得
用别人的 benchmark 推算本项目倍数。避免重复全量扫描、单个无关锁串行化全部
session、无界 writer/队列以及每次查找重复远程请求。外部案例只决定要测什么，
不强制 SQLite、overlay、线程模型或缓存实现。
